This project contains services like order, party, payment, product, transport, user, warehouse. 
We are using netflix eureka server to register the services. 

Follow these steps to setup app in your local:

1. Install java 21, postgresql and vscode(or any ide of your choice), install postman/bruno for testing, git for version management.

2. Clone the project using the link mentioned in github.

3. In each of the services(e.g. order, party, payment, product, transport, user, warehouse) go to files - \src\main\resources\application.properties.

4. Update the username and password for datasource accordingly in application.properties.

5. Change the property -spring.jpa.hibernate.ddl-auto is set from "validate" to "update"

6. Start the services begining from eureka server first and then start each application one by one.

7. hibernate.ddl-auto will make sure to create the respective schema and their table for each of the services.

8. You can skip step 5, 6, 7 and manually create schemas and tables using createSchema.txt, createTables.txt and insert-statement.txt

9. After all application successfully starts open - http://localhost:8761/ to see all registered services.

10. Also open pgAdmin to check the schemas and tables created. After making sure the schema and tables are successfully created, change 
  property -spring.jpa.hibernate.ddl-auto is set to "validate".

11. Now run insert script to have basic data to test your services. 

12. Use services.postman_collection.json files to import collections into postman or bruno.

13. Now start testing your application services by starting and testing with postman.

Happy Coding!

InventoryMate — Complete Project Reference Prompt
Project overview
InventoryMate is a full-stack B2B inventory management and billing application built for import/export and distribution businesses. A business imports goods (e.g. from China), stores them across multiple warehouses in India, takes large bulk orders from retailers and showrooms, tracks payments, and generates warehouse-wise dispatch sheets. The system is built as a React web app consuming a Spring Boot microservices backend, with a Flutter multiplatform app planned as the next phase.

Business domain
The business model is an importer-distributor. Goods arrive from overseas suppliers and are stocked across multiple physical warehouses. Sales representatives go to client businesses (parties) and book orders. Orders go through a lifecycle from creation through confirmation and payment collection. Once fully paid, dispatch sheets are generated per warehouse showing which products need to be pulled and shipped.

Shared library — auth-common
Every service depends on auth-common as a JAR. It provides:

dto/BaseUIResponse<T> — universal API response wrapper
util/ResponseBuilder — static factory for success and error responses
util/Constants — STATUS_SUCCESS, STATUS_ERROR, STATUS_SUCCESS_CODE
exception/BaseException — parent for all custom exceptions, carries code and shortMessage
exception/NotFoundException, BadRequestException, UnauthorizedException — common typed exceptions
exception/GlobalExceptionHandler — @RestControllerAdvice catching BaseException, BadCredentialsException, UsernameNotFoundException, DisabledException, LockedException, MethodArgumentNotValidException, and generic Exception. Short message in response, full stack trace in console only
security/CustomAuthenticationEntryPoint — registered in every service's SecurityFilterChain via .exceptionHandling(ex -> ex.authenticationEntryPoint(...)). Always returns 401 for expired or invalid JWT — critical fix because without this Spring Security defaults to 403 which the frontend interceptor ignores
audit/AuditFilter — OncePerRequestFilter that decodes JWT, measures request duration, and fires a virtual thread POST to the audit-trail service via Feign
audit/AuditClient — Feign interface targeting audit-trail service resolved via Eureka (no hardcoded URL)
audit/AuditClientFallback — if audit-trail is down, silently logs and continues. Never breaks the actual request
audit/AuditEventDTO — payload posted to audit-trail
config/AuthCommonAutoConfiguration — Spring Boot autoconfiguration class, scanned via META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports so every service picks up all beans automatically

Universal API response shape
Every endpoint returns:

{
  "code": "0",
  "message": "...",
  "extendedMessage": null,
  "status": "SUCCESS",
  "hasError": false,
  "responsePayload": <data>
}
On error: code is HTTP status as string, status is "ERROR", hasError is true, responsePayload is null. Extract payload with: const payload = res.data.responsePayload ?? res.data; return Array.isArray(payload) ? payload : payload.content ?? []

JWT structure
Algorithm: HS256
Claims: sub (username), role (e.g. ROLE_ADMIN), type (access/refresh), iat, exp
Access token expires in 15 minutes
Refresh token used to get new access token
All protected endpoints require Authorization: Bearer <accessToken>
Roles
ROLE_ADMIN — full access to everything
ROLE_REPS — can create orders, add line items, confirm orders, add payments, see only their own orders matched by repId
ROLE_VIEWER — read-only, can view dispatch sheets, warehouse stock, products, transport

Axios instance pattern
axiosInstance.js uses a shared queue-based 401/403 interceptor:

Attaches Bearer token to every request
On 401 or 403 response: if refresh not in progress, calls refresh-token, updates Redux, retries original request
If refresh already in progress: queues the request and resolves when refresh completes (prevents duplicate refresh calls)
On refresh failure: dispatches logout()
Each other API file imports the shared instance and sets its own base URL per request using API_CONFIG

Known patterns and gotchas
Never import store at module level in API files — use require('../store') inside interceptors to avoid circular imports. (Note: axiosInstance.js uses direct store import since it avoids the circular dependency issue there)
Never use useEffect to initialise modal form state — use lazy useState(() => EMPTY_FORM)
Always guard list state: s.list = Array.isArray(a.payload) ? a.payload : []
createPortal for dropdowns in scroll-constrained modals — attach to document.body, use onMouseDown with e.preventDefault() to prevent blur before selection
e.stopPropagation() on action buttons inside clickable table rows
Transport responses are paginated — extract via payload.content
Warehouse PATCH /products returns 403 (not 401) for expired tokens without CustomAuthenticationEntryPoint — fixed by registering it in every service's SecurityConfig
axiosInstance catches both 401 and 403 as a safety net

Audit trail service — dual database design
PostgreSQL (audit_summary table): username, role, serviceName, summaryDate, totalCalls, errorCalls, avgDurationMs. Upserted per request — rolling average duration calculated incrementally. Used for dashboard charts and aggregation queries.

MongoDB (audit_logs collection): full document per API call with TTL index (expireAfterSeconds: 7776000 = 90 days auto-delete). Used for drill-down investigation.

PostgresConfig is @Primary. MongoConfig is @ConditionalOnProperty(havingValue="true"). Both use @Enable*Repositories scoped to separate packages to prevent Spring from misrouting repository beans.

AuditService uses @Autowired(required = false) for the Mongo repository and checks isMongoEnabled() before every Mongo operation. Returns emptyPage() when disabled.
